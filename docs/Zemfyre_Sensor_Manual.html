System Connection Diagram

Physical Connections

  1. Power: Connect the ZPC400 to a 56 VDC supply. The ZPC400 delivers PoDL power over the SPE cable to each ZUS801LP — no separate sensor power supply is needed.
  2. SPE Ethernet: Run a Single Pair Ethernet (IEC 63171-1) cable from each ZUS801LP to a P0–P3 port on the ZEM601L. Use the 10-pin to 2-wire adapters as required.
  3. Ethernet uplink: Connect the ZEM601L PORT0 or PORT1 (RJ45) to the Raspberry Pi (or other processing platform) with a standard Ethernet cable.

Finding Your COM Port

  1. Plug the micro USB cable into your PC.
  2. Open Device Manager (Win + X → Device Manager) → expand Ports (COM & LPT).
  3. Note the port shown — e.g. USB Serial Device (COM4). Use that number in PuTTY.
  4. Launch PuTTY, select Serial, enter the COM port number and baud 115200.
  5. Optionally save the session as "zemfyre-sensor". Click Open; press Enter if no prompt appears.
Driver Required If no COM port appears in Device Manager, install the adapter driver first: CH340 → ch341ser.exe · CP210x → Silicon Labs CP210x VCP · FTDI → CDM FTDI drivers

2.1 Network Connection

After network settings have been configured and a system reset performed, the CLI can also be accessed remotely (Telnet/SSH) at the sensor's assigned IP address.

Prerequisite Network-based CLI access requires IP configuration via the serial connection first — see Section 3.
3
Network Configuration
IP addressing convention used in this manual Raspberry Pi (MQTT broker, eth0): 192.168.2.30 · Sensors: 192.168.2.100, 192.168.2.101, 192.168.2.102 … · Gateway: 192.168.2.1. Adapt to your network as needed — the sensor and broker must be on the same subnet.

Configure Raspberry Pi Host Interface

sudo nmcli connection modify eth0 ipv4.method manual ipv4.addresses "192.168.2.30/24"
sudo nmcli connection up eth0
ip -4 addr show eth0

View & Set Sensor Network Binding

# Show current network settings
eth -ifconfig

# Set device IP address (first sensor = .100, second = .101, etc.)
eth -ifconfig ip 192.168.2.100

# Set gateway
eth -ifconfig gw 192.168.2.1

# Set subnet mask
eth -ifconfig sn 255.255.255.0

# Set DNS servers (optional)
eth -ifconfig dns0 8.8.8.8
eth -ifconfig dns1 8.8.4.4

# Verify all settings
eth -ifconfig
System Reset Required Network changes are written to EEPROM but do not take effect until: core -reset

Apply Changes & Verify

core -reset

# Test connectivity after reboot
eth -ping 192.168.2.100

After reset, the sensor comes back online with the new network settings. The LED changes to green toggling once MQTT is also configured.

4
MQTT Broker Setup

Verify Mosquitto on the Host

docker ps | grep mosquitto
ss -ltnp | grep 1883
mosquitto_sub -h 127.0.0.1 -p 1883 -t '#' -v

Configure MQTT on the Sensor

# View current MQTT binding
eth -mqtt

# Set broker IP address
eth -mqtt ip 192.168.2.30

# Set broker port
eth -mqtt port 1883

# Alternative: set by hostname/URL
eth -mqtt url "mqtt-broker.local"

# Verify configuration
eth -mqtt

# Apply changes
core -reset

# Monitor publish statistics
eth -mqtt stats

LED Status Reference

Success Indicator Solid green LED means the sensor is fully operational. Data should now appear in InfluxDB and the Grafana dashboard.
Security The ZUS801LP supports TLS 1.2 and TLS 1.3 for encrypted MQTT transport, plus an onboard Secure Element (SE) with cryptographic accelerator and secure key storage. Configure TLS in the MQTT broker and sensor firmware settings as needed for production deployments.

Grafana Dashboard Access

Starting the Docker Stack

cd ~/zemfyre-sensor
docker compose up -d

Method 1 — Zemfyre Admin Panel (Recommended)

The Admin Panel at port 51850 is the intended end-user interface. It opens Grafana inside a fullscreen, clean iframe with no Grafana navigation bars or login prompts — exactly like a kiosk display.

  1. Open a browser and navigate to http://192.168.2.30:51850
  2. The Zemfyre Admin Panel loads with a dark navigation bar at the top showing the Zemfyre logo.
  3. Click the Dashboard button in the top navigation bar.
  4. The Grafana dashboard opens in a fullscreen iframe — no login required, 1-second auto-refresh active.
  5. To switch sensors, click the Sensor ▾ chip at the top-left of the dashboard and select SENSOR_1, SENSOR_2, etc. (see Figures 1 & 2 below).
Why use the Admin Panel? Port 51850 provides a cleaner experience: no Grafana header/sidebar, no sign-in screen, direct fullscreen dashboard view. It also gives access to Settings (time sync, database management) in one place.

Method 2 — Direct Grafana Access (Advanced)

Use direct Grafana access to create or edit dashboards, manage data sources, or explore the InfluxDB query builder.

Selecting a Sensor

The dashboard supports multiple sensors simultaneously. Click the Sensor ▾ chip at the top-left of the dashboard to open the selector — all panels instantly update to show data from the chosen device. Sensors appear as SENSOR_1, SENSOR_2, SENSOR_3, SENSOR_4, corresponding to IPs 192.168.2.100, .101, .102, .103.

6.1 System Commands

core — System Control
core -status      # System status overview
core -reset       # Apply config & reboot
core -version     # Firmware version
os — OS Diagnostics
os -get rt        # OS runtime in ms
os -get stats     # Scheduled task info
app — Application
app -state dia    # Enter diagnostics mode
app -state exit   # Exit / reset
app -display on   # Show readings in CLI
app -display off  # Hide output (default)
app -poll <ms>    # Set polling interval
app -poll get     # Get polling interval
tasks — Task List
tasks             # List active tasks

# ── Ethernet / network ─────────────────────────────────────────

eth -ifconfig gw  <x.x.x.x>      # Set gateway

eth -ifconfig dns0 <x.x.x.x>     # Set primary DNS

6.3 Sensor Commands

sensor — Sensor Manager

sensor -list          # List all available sensors
sensor -status        # Initialization status per sensor

bm688 / bme688 — BME688 Environmental Sensor

bm688 -setoff temperature <val>  # Temperature offset (°C)
bm688 -setoff pressure <val>     # Pressure offset (Pa)
bm688 -setoff humidity <val>     # Humidity offset (%rH)
bm688 -get offset                 # Show all offsets

adxl345 — Accelerometer

adxl345 -report set on    # Enable reporting (reset required)
adxl345 -report set off   # Disable reporting
adxl345 -report get       # Get current state

vl53 — VL53L4ED Time-of-Flight Proximity

vl53 -setoff <mm>     # Set calibration offset in mm
vl53 -get offset       # Show all configured offsets

bh1750 — Ambient Light Sensor

bh1750 -h              # Show command help

6.4 EEPROM, Device & LED Commands

eeprom — Non-Volatile Storage

eeprom -erase              # Erase all EEPROM
eeprom -default            # Erase & restore default IP bindings
eeprom -pgerase <n>        # Erase page n only  (0 ≤ n ≤ 7)
Warning — Destructive eeprom -erase and eeprom -default clear all network and MQTT configuration. Re-enter all settings and core -reset after running.

name — Device UID

name -set <name>           # Set custom device name
name -get                  # Return device name

stsled — Status LED Control

stsled -r on/off/dc        # Red channel on / off / duty-cycle
stsled -g on/off/dc        # Green channel
stsled -b on/off/dc        # Blue channel
stsled -RGB 0xRRGGBB       # 24-bit colour blend  e.g. 0x00FF00

i2c — I2C Bus Diagnostics (Advanced)

i2c bus0 -if up/down       # Interface up or down
i2c bus0 -read             # Current-index read
i2c bus0 -rread a=<addr> cl=<len> rl=<len> cmd=<d0:d1>
i2c bus0 -write            # Write operation
i2c bus1 <options>         # Same for bus 1

Troubleshooting

LED Stuck Yellow

  • Check MQTT broker IP/port: eth -mqtt
  • Confirm Mosquitto running: docker ps | grep mosquitto
  • Confirm port 1883 open: ss -ltnp | grep 1883
  • Test reachability: eth -ping <broker-ip>
  • After fixing, apply with core -reset

No Serial Connection in PuTTY

  • Verify COM port in Device Manager → Ports
  • Install correct driver (CH340, CP210x, or FTDI)
  • Try baud rates: 9600, 57600, 115200
  • Check physical cable and adapter connections

Network Settings Not Applied

  • Always run core -reset after network changes
  • Verify IP does not conflict with another device
  • Check SPE cable connection and termination

Sensors Not Initializing

  • MQTT must be configured before sensors start — configure and reset first
  • Verify power supply meets specifications
  • Run sensor -status to identify which sensors failed

Grafana Shows No Data

  • Confirm solid green LED (MQTT connected)
  • Listen for MQTT: mosquitto_sub -h 127.0.0.1 -p 1883 -t '#' -v
  • Check Node-RED flow: http://<Pi-IP>:51880
  • Check InfluxDB: http://<Pi-IP>:58086

Setup Checklist

Hardware

  • Sensor power supply connected and power LED on
  • SPE Ethernet cable connected
  • USB-to-Serial adapter installed with correct driver
  • PuTTY configured: Serial · correct COM port · 115200 baud
  • Serial CLI accessible — help returns output

Network Configuration

  • Raspberry Pi eth0 on sensor subnet (e.g. 192.168.2.30/24)
  • Sensor IP set: eth -ifconfig ip 192.168.2.100
  • Gateway set: eth -ifconfig gw 192.168.2.1
  • core -reset performed after network changes
  • Ping successful: eth -ping <sensor-ip>

MQTT Configuration

  • Docker stack running: docker compose up -d
  • Mosquitto listening on port 1883
  • MQTT broker IP configured: eth -mqtt ip 192.168.2.30
  • MQTT port configured: eth -mqtt port 1883
  • core -reset performed after MQTT configuration
  • Status LED is solid green
  • MQTT messages visible with mosquitto_sub

Grafana Dashboard

  • Grafana accessible at http://<Pi-IP>:51850
  • Dashboard loads and shows sensor panels
  • Temperature, Humidity, Pressure, Gas panels show live values
  • Dashboard auto-refreshes every 1 second

Final Validation

  • All 8 sensor measurements reporting data (temperature, pressure, humidity, air quality, light, sound, proximity, acceleration)
  • MQTT publish stats clean: eth -mqtt stats
  • All sensors initialized: sensor -status
